# Service Framework

## outline

1. 支持分布式
2. 动态或低成本拆分
3. 初始化、启动、停止、销毁等流程化
4. 无配置智能发现或感知服务
5. Future同步写法

## proposal

- service能在一个进程里，也可以方便进行拆分，以用于后期考虑分布式部署
- service之间通讯需要封装进程内和进程间通讯
- 上层不区分通讯是通过function、network、MQ等具体实现
  - 主要为本地函数调用
  - NSQ信息队列（性能优化，现在只有千级QPS）
  - msgpackrpc（考虑废弃，保持nsq一套）
- 对非逻辑的错误需要统一定义和相关处理（无法统一的话如何？）
- 针对具体的不同通讯实现，超时、重试交由上层决定
- 进程内需要保证线程安全
- 进程间需要保证调用和返回的顺序一致性
- service接口导出规则
